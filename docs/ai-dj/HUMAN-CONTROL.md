# Operating modes and playing B2B with the AI

## Three operating modes

| Mode | Authority | AI behavior | User behavior |
| --- | --- | --- | --- |
| AI Only | AI owns the performance controls while armed. | Organizes the full set and executes it. Ordinary manual adjustments do not create a B2B hold; re-evaluate observed state and promptly restore the intended performance through smooth, bounded actions. | Can observe and edit future set constraints. Use Disarm AI or change mode to take performance authority. |
| B2B | Human input overrides AI on the affected controls. | Arranges and performs the set, yields individual controls during human gestures, and may regain them at a later transition start after release, the quiet period and reconciliation. | Mix alongside AI using physical controller, mouse or keyboard; pin a control or disarm whenever desired. |
| Playlist Only | Human owns all live performance. | Arranges, edits and saves the set list. It may read host state and perform an explicit playlist-save operation, but sends no load/play/cue/seek/sync/EQ/fader/effect or other performance commands. | Loads tracks and performs the mix. AI playlist planning does not imply AI playback. |

“Playlist Only” still uses AI for organizing music; it disables AI mixing. Its completed deliverable is a saved/ordered set list, not a claimed performed set. Read-only MIDI requests and explicitly requested library writes are separate from the disabled performance executor.

Delegated first-launch selection is B2B, with automation disarmed on launch. Selecting AI Only is an explicit choice to give AI performance authority. Disarm AI is a global priority in all modes and remains latched; ordinary controller changes cannot cancel it. Existing guards against active-deck replacement, stale state and unbounded gain remain in AI Only. Overriding a manual change means replanning a valid recovery, not blindly replaying old MIDI or abruptly replacing an audible track.

Switching modes increments a mode epoch, cancels prior-mode queued actions and releases AI-owned momentary controls before allowing new actions. Reject late old-epoch results/plans/commands at both executor and host bridge. Refresh observed state. Entering Playlist Only stops performance automation while current audio keeps playing; an already-armed switch between AI Only and B2B continues after cancellation and reconciliation without another resume action. An explicit disarm remains latched. Selecting AI Only or B2B from Playlist Only requests performance start after reconciliation, without another Start action. This does not clear an explicit Disarm AI latch. Mode preference can persist, armed state cannot. Desktop UI must show selected mode, armed state and per-control authority separately.

## B2B product behavior

The human and AI share Mixxx like two DJs playing back to back. A real MIDI controller stays connected directly to Mixxx using its normal mapping. Our desktop service uses separate virtual MIDI command and feedback routes. The mouse, keyboard, physical controller and AI can all change Mixxx; the AI follows the host's observed state.

A human adjustment takes priority over automation on the affected control. If the user turns bass down during a transition, stop queued and ongoing AI bass updates immediately. Other independent work may continue, but dependent transition steps must pause or replan. Do not disarm the entire set for one EQ adjustment.

A prominent **Disarm AI** button, a keyboard shortcut and an assignable physical MIDI-controller button stop future AI commands, cancel queued automation and release AI-owned momentary actions. It leaves the current music playing. It must reach the communicator directly without waiting for the planner. Explicit disarm is latched until the user chooses Resume AI; automatic debounce never overrides it.

## B2B per-control state machine

`AI available → human adjusting → held for this transition → quiet and released → later transition start → reconcile → new AI action`

1. On manual intent or an unexplained divergence from AI observations, increment that control's ownership generation and cancel its pending writes. The host mapping must reject superseded queued requests where possible. Already applied writes cannot be undone by cancellation.
2. During human adjustment, continue receiving observations. Reset the quiet timer on every relevant input, including repeated identical values when input-intent telemetry is available. Related controls have dependency rules: loading or seeking a deck can invalidate the entire transition, while one EQ band ordinarily affects only that band.
3. Default quiet period is **3 seconds**, configurable per controller/control and measured with a monotonic clock. The user confirmed this default in Round 2, question 3. It is not a latency allowance for the initial yield.
4. A reported touch must be released before the quiet period can expire. With no touch/intent telemetry, label detection as inferred inactivity; unchanged-value contact cannot be reliably detected from host value feedback alone.
5. Hold the affected item for the rest of the current transition even after quiet expiry. At a later transition start, require release, elapsed quiet time, fresh host state, current track/ownership generations and no explicit hold/disarm. If not eligible, carry the hold forward. A gesture between transitions can be reclaimed at the next transition only if these conditions are met.
6. Resume only with a newly valid action at that eligible subsequent transition, starting from the human's current value. Rate-limit/ramp continuous values. Never resume the old curve or instantly restore its abandoned target. If the planner is late or no safe action exists, leave the user's value in place.

For the bass example: AI target 0.6, user moves it to 0.2, AI yields bass, the user continues turning it, and the timer keeps resetting. After the last movement plus the quiet period, bass still stays at the human value throughout the current transition. At a subsequent eligible transition AI may begin a new gentle move starting at 0.2. A full-band cut must not be undone merely because the timer expired. The planner must account for that live musical change; the operator can pin a control if they want it kept manual indefinitely.

## Implementation boundaries

Mixxx's shared control feedback supplies values, not universally reliable source or touch identity. Our own request correlations can identify some expected observations, but a coincident matching human value is still ambiguous. Never infer that every matching value is definitely ours, or every difference is definitely a person. In B2B prefer yielding on unexplained divergence; in AI Only reconcile and create a bounded recovery action.

Add a versioned manual-intent/touch hint where the selected controller mapping can report it without changing its normal behavior. Do not require an arbitrary controller to emit undocumented touch messages. The capability profile must distinguish value-only inference from explicit input/touch detection. If the selected hardware cannot expose touch, test and disclose that limitation; the disarm and pin controls remain reliable operator choices.

Do not route physical commands back into the AI command bus. Mixxx feedback can inform all listeners without creating new commands. Preserve hardware soft takeover/pickup behavior; when AI changes a value, the physical controller's mapping must avoid a jump on the next manual movement. Validate knob, encoder and touch-sensitive configurations separately rather than claiming one fixture proves every controller.

In B2B the planner receives holds as constraints. It cannot clear a human hold or call MIDI directly. Cancellation, release, debounce and ownership live in the deterministic communicator/host mapping. A stalled AI process cannot prevent yielding. Host and controller watchdogs must release only their owned cue/scratch actions on loss; do not send an indiscriminate all-controls reset.

## Acceptance scenarios

- In AI Only, move bass below the AI plan: confirm the AI observes it, does not enter a B2B quiet hold, and smoothly recovers to a valid planned value while armed. Press Disarm: all further AI recovery stops.
- In Playlist Only, arrange and save a playlist while moving real controls: assert the app emits zero performance MIDI messages, including deck loading, and does not count an arrangement as a performed set.
- Switch AI Only to B2B or Playlist Only while a curve is queued: the previous mode's pending curve cannot run. Reject late results. Already-armed AI Only/B2B switches continue after reconciliation; explicit disarm remains latched.

- Sustain a bass gesture for longer than 3 seconds: AI stops bass writes promptly, observes every emitted value, and never resumes between intermediate events. Other independent controls remain usable.
- Move bass again at 2.9 seconds: the quiet timer restarts. No resumption occurs at the old deadline.
- Let go during a long transition: after 3 seconds, bass remains human-owned and receives no AI writes for that transition. At the next eligible transition, new motion begins from the user value with a bounded slope. The abandoned curve never resumes.
- Keep touching across the next transition start: it cannot reclaim the control. Quiet expiry later in that transition still does not reclaim it; wait for another eligible transition start.
- Hold touch without changing value: explicit touch telemetry keeps the hold; value-only profiles report their detection limit and do not claim touch knowledge.
- Turn EQ and crossfader concurrently: independent holds work, but a fader action that invalidates blend completion pauses the dependent transition.
- Send a late AI write after a human gesture: stale ownership generation is rejected; test the cancellation race at the host as well as in Node.
- In B2B, manually replace the AI-selected song: cancel actions for the old track generation, confirm the new identity/state and adapt the transition and remaining set to the human choice. Prove that no stale command reloads the old choice and no displaced occurrence is falsely marked played. Apply existing human control holds. Test manual seeks separately for position reconciliation.
- Disarm while the model is stalled: cancel AI output while audio continues. Waiting longer than the debounce does not rearm it.
- Disconnect feedback or restart: automation remains disarmed with unknown/stale state until reconnect, a new snapshot and deliberate rearming.
- Exercise the physical controller and mouse in the final full-playlist set; retain MIDI/state, UI and audio evidence. Synthetic input tests do not certify hardware feel.

## Additional handover rules from delegated discovery

Manual Pause/Stop in B2B creates a latched transport hold for that deck: no AI play, cue trigger or replacement load until human playback or explicit deck release. Other independent work may continue. Per-control/deck pins require explicit release; their release still needs reconciliation and an eligible later transition. These holds are distinct from global Disarm.

A transition has a stable ID and explicit planned start, active interval and completion/cancellation outcome. A later transition means a genuinely subsequent musical handoff, not a new ID attached to the abandoned curve. Cancellation, replanning or a manually loaded track cannot manufacture a boundary to evade the human hold. If a required control remains held at the next start, retain the hold and choose a valid alternative or wait.

When the user loads a replacement, preserve it, replan from actual identity/playhead/loop state, and keep the displaced occurrence available later unless explicitly skipped. Manual additions are allowed even when AI selection is playlist-restricted; record their origin without silently changing the pool setting. Existing controller mappings and supported pickup behavior remain authoritative.

A planner failure can use a validated deterministic fallback only with fresh host state and current authority. Essential feedback loss disarms. Do not confuse a disconnected physical controller with trustworthy release of its held controls. Acceptance must exercise manual stop, explicit hold release, changed track identity, stale fallback, and controller disconnect as distinct cases. See [R2 defaults](DEFAULTS.md#round-2-defaults).
