# AI DJ evidence capture format

> This document was autonomously generated by an AI agent at the user's request.

This convention defines a portable, privacy-aware record for later MIDI, Mixxx, UI, audio, timing, and listening evidence. A schema-valid record describes what was captured; it does not by itself prove a host effect, native UI behavior, audible outcome, or musical quality.

## Required run header

Every evidence record names the run ID, source revision, schema version, local session ID, host instance ID, connection generation, profile ID/revision, capability revision, state revision, and the selected local monotonic clock ID. Record the operating system, Node version, Mixxx version/build, skin/configuration, and fixture identities separately. Keep operator music paths, controller serial numbers, credentials, and unrelated personal metadata out of the record.

## Clocks and ordering

Every structured event has a local monotonic `atMs`, a local capture time, and a monotonic capture sequence. If an event originated in host, UI, or audio time, retain its source clock-domain ID and numeric source timestamp. A clock-domain record declares its unit and whether conversion to the local monotonic clock is local, calibrated with an uncertainty, or unmapped. Report calibration method, calibration time, uncertainty, drift checks, and any unresolvable mapping. Do not compare timestamps across domains or label a round trip as one-way latency without this evidence.

Capture sequence is the recorder's ordering evidence, not a claim about causality. Preserve same-time events, out-of-order arrivals, source timestamps, and correlation IDs. A lost or paused region is an explicit gap with the first and last missing capture sequence, dropped-event count, and whether the range is contiguous.

## Evidence classes

Keep these event kinds separate in raw data, summaries, and conclusions:

| Event kind | It records | It does not prove |
| --- | --- | --- |
| `command-sent` | A known local transport submission and its attempt/message IDs. | Host acceptance, state change, visible UI, or audio. |
| `host-observed` | A returned host observation and its status/evidence IDs. | Causation by a command, native UI visibility, or audible onset. |
| `ui-observed` | A reported UI surface/render revision, optionally linked to a capture artifact. | That a native Mixxx surface changed unless the artifact and review establish it. |
| `audio-observed` | A captured audio-clock sample position and optional capture artifact. | A causal link to a command or a subjective quality outcome. |
| `raw-recorded` | Copied raw MIDI bytes from its named direction or unmapped source. | Decoded musical meaning, actor, host acceptance, or lossless capture. |

Requested, sent, accepted, host-observed, UI-observed, audio-observed, uncertain, rejected, cancelled, and expired outcomes remain separate. A later analysis may link them only with explicit correlation and uncertainty; never infer a missing intermediate result.

## Artifacts and redaction

Each raw MIDI, audio, UI capture, or timing-log artifact has an opaque artifact ID, manifest revision, content type, byte length, capture clock ID, capture time, and an opaque local reference. The shareable manifest removes absolute paths, device identifiers, filenames, free-form notes, credentials, and other unneeded metadata. Audio and waveform assets are opt-in; their absence is recorded as unavailable rather than silently substituted. Store large artifacts outside source control and retain only redacted references in exported evidence.

## Bounded capture and reporting

The recorder queue has a declared capacity and reports offered, accepted, queued, and dropped event counts. When it overflows, it records an explicit gap instead of claiming complete capture. Capture, export, analytics, and rendering stay off the MIDI callback/hot path. Any disk failure, paused recorder, partial artifact, shutdown interruption, unknown source, or clock-mapping failure remains visible in the result.

## Minimum result statement

Each run evidence document reports exact commands, source revision, environment, selected fixtures, clock domains, artifact manifests, event counts by kind, sequence gaps, failed checks, and the conclusion's scope. It labels unit, simulated, direct-service, real-Mixxx, native-UI, audio-capture, controller, endurance, and listening evidence accurately. Later reviews must preserve negative results and unresolved uncertainty.
