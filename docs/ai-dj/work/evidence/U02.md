Session cookies are HttpOnly and SameSite=Strict; per-session request tokens remain in browser memory and are required for API requests. Bodies and client WebSocket messages are bounded at 4 KiB. Static assets use fixed paths, no-store, no-referrer, nosniff and a restrictive same-origin CSP.

WebSocket transport uses pinned `ws` 8.21.3 with compression disabled; browser clients use native WebSocket. Installation audited eleven packages with no reported vulnerabilities. The implementation follows the project's [official authentication and server guidance](https://github.com/websockets/ws). This dependency observation is not a complete security audit; L02 remains open.

No replay window or delta support is claimed: reconnect always clears derived state and receives a fresh snapshot. The browser rejects sequence gaps, conflicting duplicates, foreign instances, incompatible clocks and any shell message claiming performance authority. Identical duplicates are ignored. At most one publication is outstanding pending an application ACK, a stricter bound than the proposed 2,000 publication limit. Publication size is capped at 1 MiB and buffered bytes at 4 MiB; failure to ACK for three seconds closes with `resync-required`.
