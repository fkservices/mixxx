# Raw physical-controller capture operation

> Autonomously AI-generated O02 design at the user's request. This specifies required implementation; it is not an installed capture hook.

## Outcome and capture boundary

The physical controller continues to connect directly to Mixxx. A native observer copies input evidence before mapping, learning, conversion or host filtering. It cannot consume a message, replace its mapping, change a value or reroute the controller. The companion receives copies on the separate, configured AI DJ feedback endpoint. No assumption is made that macOS or a MIDI library permits a second process to tap the same physical input.

For the current macOS PortMidi host, the exact hook is `PortMidiController::poll`, immediately after a successful `PortMidiDevice::read` and before the per-event status/SysEx branch. Observe every returned `PmEvent` once, including an event that the existing parser later revisits using `reprocessMessage`. Preserve backend delivery order. Short-message and completed-SysEx mapping callbacks are too late: `MidiController::receivedShortMessage` drops F8 before mapping, and `MidiController::receive` sees only assembled SysEx and routes it through declared mappings. The existing 1,024-byte SysEx assembly can truncate what mapping code sees. The new observer must retain fragments before that truncation without changing legacy delivery.

Capture scope is **all events delivered by the configured native backend while the selected endpoint is open and capture is enabled**, with explicit loss and provenance. It does not prove the original electrical byte stream, restore running-status bytes removed by a driver, or capture input that the OS/backend never delivered. A disabled/unopened endpoint is not continuously captured. HID and HSS1394 controllers need their own hooks before those backends can be advertised as covered.

`Controller::startEngine`, the legacy script engine's `engine` object registration, and the base engine's controller/midi proxy expose the bridge integration locations. Do not call a QJSEngine from the poll hook or assume a script callback shares manager-thread affinity. The bridge must marshal through a bounded mailbox to the configured script owner and enforce thread assertions. No raw QObject pointer may outlive endpoint retirement.

The installed build's pinned PortMidi header documents backend packet packing and filtering. Public reference: [PortMidi header](https://github.com/PortMidi/portmidi/blob/master/pm_common/portmidi.h). Short messages occupy one packed word with unused high bytes. SysEx occupies successive four-byte packets; real-time packets can be delivered before partially accumulated SysEx bytes. Backend timestamps are not interchangeable with the host monotonic clock. Those are reasons to retain backend evidence rather than present padding or normalized order as original wire bytes.

## Native packet, identity and loss contract

Proposed native `RawMidiCapturePacket` is fixed-size POD, at most 64 bytes: endpoint slot/generation, producer sequence, packed unsigned 32-bit message, original signed 32-bit backend timestamp, and host monotonic capture stamp. Use `mixxx::ControllerMonotonicClock::nowMilliseconds` for the host stamp and a distinct explicit backend-clock label for the original timestamp. Sample at the read boundary; the stamp measures host receipt, not physical contact time. Preserve wraps/regressions in backend timestamps; do not clamp or relabel them as a new host epoch.

Each selected endpoint gets a new opaque identity and producer stream epoch on successful open. The cold-path descriptor includes backend/interface/name, input/output indexes separately, host instance/build, mapping revision, configured endpoint role, and identity confidence. Device names are descriptive, not primary keys. Role and mapping changes retire the old descriptor, cancel pending attribution and issue an explicit new epoch. Startup, stop, mapping reload, read loss, reconnect and shutdown have ordered lifecycle records with unknown counts where the backend provides none. Physical capture does not establish a resulting host control change; actor stays unknown or inferred until separate endpoint/dispatch evidence supports it.

Read errors retain the existing `notifyInputLoss` behavior. A backend overflow reports unknown lost-event count: negative `Pm_Read` is not a count of dropped MIDI events. Capture-ring overflow reports exact missing producer sequences. Neither condition fabricates play/stop/reset bytes. Every close carries the final producer watermark so a trailing loss is visible even if no later packet arrives. No reconnect resumes an old stream or closes an unknown loss interval by guessing.

Raw recording must explicitly enable `Pm_SetFilter(stream, 0)` when supported, and record the effective mask/error outcome. Newly visible FE active-sensing input is copied but must retain the pre-capture legacy behavior of not reaching mappings or activity handling. When capture is disabled, restore the declared prior filter policy. Reject capture activation or label coverage incomplete if filter configuration fails; leave normal controller operation available. Do not silently claim active-sensing coverage from a post-read hook using default filters.

## Bounded observer and transport

Initial maximum: 32 explicitly selected endpoints, 4,096 fixed 64-byte slots per endpoint (8 MiB packet storage total), plus a separately bounded descriptor/lifecycle budget of at most 1 MiB. Enabling endpoint 33 fails visibly without pretending it was captured. Allocate buffers and immutable descriptors outside poll/receive paths. The manager-thread producer only stamps, copies into a preallocated SPSC channel and updates atomic counters. No JSON, logs, file I/O, MIDI sends, waits, locks, per-message Qt queued signals, arbitrary callbacks or allocations in that producer path.

The single drain consumer processes at most 64 packets per endpoint visit, rotates fairly and never waits for a full message. Sequence numbers advance for every offered backend event. Drop newest on saturation, preserving queued records. Consumer sequence gaps expose missing ranges; a release/acquire published watermark and drop counter establish trailing losses after draining to that watermark. Snapshot reads must use a bounded consistent-publication protocol; at most two attempts, otherwise report unavailable and retry later. Never infer a gap from a watermark sampled ahead of an unpublished ring write. Test overflow at wraparound, concurrent reads and endpoint retirement, not only a single-thread queue fixture.

The bridge owns one immutable batch pending acknowledgement per subscriber, at most 64 packet records and 16 KiB encoded payload, with a hard 250 ms lifetime. New source records remain in bounded native rings while a batch is pending; loss counters continue. Late or duplicate ACKs cannot drain a new epoch. A replay of the retained batch keeps identical IDs/bytes and is read-only; expiry records delivery uncertainty and starts a fresh resynchronization boundary rather than growing a retry queue. R01's 65,536-byte and 128-fragment maxima remain outer limits, never an excuse to enlarge this operation.

Send copies only over the configured AI DJ virtual feedback route, using the accepted bounded fragment sender and current R06 lifecycle identity. Physical controller outputs remain untouched. Heartbeats, cancellation and urgent manual-intervention notices outrank bulk raw recording. Do not use bulk completion as the sole B2B human-touch signal: R18/O06 must prove their priority dispatch/attribution path and human-recognition deadline separately. If raw traffic exceeds available transport/recorder capacity, show gaps; never stall Mixxx mapping or coalesce away raw gestures to make the timeline look complete.

Proposed C++ entrypoints are `RawMidiCaptureBuffer::offer/drainThrough/status`, `RawMidiCaptureBridge::takeBatch/acknowledgeBatch/status`, and a setup-only `ControllerManager::configureRawMidiCapture`. `Controller::setRawMidiCaptureAccess` attaches an immutable, revocable access handle; `ControllerScriptEngineLegacy::initialize` exposes the dedicated read-only bridge only when its controller has that handle. These are proposed additions, not existing callable methods. An ordinary controller mapping receives no handle. Bridge teardown retires access before script shutdown and keeps only bounded immutable packet storage alive until the consumer releases it.

The setup-controlled capture enablement is local and explicit; receiving a MIDI request alone cannot enable capture of arbitrary endpoints. Expose only the fixed capture operation to the configured AI DJ script instance. No generic invoke, arbitrary property access, dynamic source evaluation, filesystem path or output-device selection comes from a wire payload. Starting/stopping raw capture never grants performance authority or rearms the AI.

## Companion and session representation

First implement and validate a **backend evidence extension** before connecting capture to the recorder. The current raw-midi event has no field that safely represents a packed backend word and its original timestamp. Add a closed `backend-midi-packet` event to the unreleased session contract, with backend `portmidi`, endpoint identity, packedWord uint32, original timestamp int32, effective filter mask and delivery-order scope `backend`. This is backend evidence, not a synthetic four-byte MIDI message. Carry it through storage/export/import as data; unknown readers must reject unsupported kinds explicitly. Keep existing v1 fixtures compatible and update session admission/documentation deliberately.

A bounded converter may additionally emit linked `raw-midi` events. Determine short-message byte count from status, omit unused word padding, preserve Note On velocity zero as raw bytes and preserve the sequence of received backend fragments. For SysEx, retain fragments independently; optional semantic reassembly is bounded to 64 KiB and never controls raw retention. Interleaved real-time messages remain separate events. Unknown/truncated/malformed words retain their backend packet; do not invent raw bytes, MIDI direction, completion, semantic label or actor. Sequence gaps retire pairing/reassembly state. Every derived raw event links its backend event and uses a distinct immutable event ID, preventing double counting as a second physical gesture.

O05's verified declarative profile supplies musical meaning after admission; an unknown control remains raw. O06 links dispatch and resulting host observations when proven. Record the two as separate facts. O07 receives admitted encoded events through its existing bounded ingress; capture failures and omitted-offer accounting remain visible to the service and eventual timeline. History never submits recorded packets back to a MIDI handle.
