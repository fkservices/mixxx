## Routes and byte framing

Every listed packet is exactly three bytes: status, address, value. All addresses and values are integers in `0..127`; status includes the zero-based MIDI channel nibble. Human channel numbering is 1–16. The packet specification below uses hexadecimal; the JSON uses decimal integers. Commands use channels 1, 2 and 3; feedback uses 9, 10 and 11. This distinction is defense against accidental loopback, not endpoint identity evidence. Never forward feedback to commands. ## Frozen semantics and scaling

The future mapping must use the fixed scripting API binding in the profile. XML toggle defaults or direct MIDI button modes do not implement this specification. Host binding strings identify reviewed adapter data and cannot be accepted in a planner action. F06's closed semantic union remains the only action interface.

**Play:** `deck.set_playing` writes an explicit `0` or `1` through `engine.setValue(group, "play", value)`. Incoming CC value zero means false; any `1..127` means true; canonical emission is `0`/`127`. Repeating on means request on again, never pause. There is no release message for this CC setter: Note Off at the same numeric address is unrelated. Read `[ChannelN],play`, not `play_indicator`. The host may reject or alter the requested state, including during cue preview. The `play` value also includes cue preview and play-after-loading intent; known loaded identity, no active preview and load reconciliation are required before interpreting it as ordinary playing. It does not prove sound or audible participation. [Tagged play request handler](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/enginebuffer.cpp#L776) and [2.5 control reference](https://manual.mixxx.org/2.5/en/chapters/appendix/mixxx_controls#control-channeln-play).

**Volume:** `deck.set_parameter`, parameter `volume`, means normalized fader travel `n` in `[0,1]`. Decode `n=v/127`; encode `v=floor(127*n+0.5)`. The mapping writes `engine.setParameter` and reads `engine.getParameter`. It must not write the normalized travel directly as raw gain. The released channel fader is an audio taper with minimum parameter endpoint silence, maximum unity gain, `minDB=-20`, `maxDB=0`, neutral travel `1`. Its raw gain is `(10^((20*n-20)/20)-0.1)/0.9` for `0<n<1`, with endpoints `0`/`1`. At MIDI 64, travel is `64/127`, raw gain approximately `0.243452775`, neither half gain nor unity. Invert with the host parameter API for feedback, then round to 7 bits. Maximum travel quantization error is `1/254`. [Tagged volume construction](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/enginemixer.cpp#L888) and [audio taper conversions](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/control/controlbehavior.cpp#L170).

**Crossfader:** `mixer.set_parameter`, parameter `crossfader`, uses normalized travel. Preserve the conventional exact center at byte 64: decode `n=v/128` for `v<=64`, otherwise `n=(v-1)/126`. Encode `floor(128*n+0.5)` for `n<=0.5`, otherwise `floor(126*n+1+0.5)`. Write/read with the parameter API; raw host value is `2*n-1`. The endpoint/center values are `-1,0,1`; maximum travel quantization error is `1/252`. This matches the released potmeter MIDI curve and is deliberately different from the volume curve. Fader position is not an equal-power or audibility guarantee: channel orientation, reverse, curve and output routing remain independent. [Tagged potmeter conversions](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/control/controlbehavior.cpp#L70) and [crossfader construction](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/enginemixer.cpp#L104).

Reject nonfinite/out-of-range normalized semantic values; do not silently clamp them into valid commands. Quantization occurs only after semantic admission. Feedback rounding applies only after validating the actual finite host parameter in `[0,1]`. Invalid readings become unknown, not zero.

**Momentary cue:** select `cue_preview`, not `cue_default`, `cue_cdj`, `cue_set`, `cue_goto` or an indicator. A positive Note On writes `1`; zero-velocity Note On and **every Note Off velocity** write `0`. Canonical press is velocity 127 and canonical release is Note Off velocity zero. There is no velocity-to-gain behavior. With a valid main cue, positive input seeks to it and starts preview; releasing an active main preview stops and seeks back. The released handler ignores a positive repeat while already previewing and does nothing when the main cue is invalid. Ordinary play or another cue can change that state, so repeat/release behavior is not a reliable lease protocol. Require the expected loaded track, known cue and paused target for the initial fixture; preserve the existing marker. [Tagged cue implementation](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/controls/cuecontrol.cpp#L1385).

Cue feedback on `B8/B9 23` is explicitly **control-signal-only**: it reflects the `cue_preview` input control, normalized to `0`/`127`, and may remain high after an ineffective press or intervening playback action. It is not an observation of an active hold, a successful seek, an actor, a particular F06 press lease, or release completion. The profile marks production semantic cue execution `extension-needed`, with `mixxx.cue-lease-guard.v1`. M07 may demonstrate bounded raw press/release in an exclusive fixture; admitting `deck.cue_press/release` in production additionally needs track/press binding, host-side guard/watchdog and independently verified cleanup. Do not weaken F06's lease cleanup guarantees to make raw notes appear sufficient.

**Sync:** select **desired sync lock enabled/disabled**, by `engine.setValue(group, "sync_enabled", 0|1)`. CC decoding/emission matches play. This requests participation in Mixxx's sync system. It neither sends a press/hold gesture nor forces a named leader, exact BPM, phase offset, or beat deadline. Enabling requests follower mode but the engine may select a soft leader; disabling removes the target's participation. Enabling can affect other sync participants and can change tempo/phase. Passthrough rejects enable; follower mode can disable vinyl control. If enabled then disabled before an audio callback, the engine explicitly handles that pair as one-shot sync. Therefore do not pulse this setter, automatically send a release, blindly retry, or assume rapid cancellation undoes musical effects. Observe the engine-confirmed `sync_enabled` boolean; assess tempo, phase and participants separately. [Tagged boolean request](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/sync/synccontrol.cpp#L511), [queue behavior](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/enginebuffer.cpp#L413), [engine mode/leader selection](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/sync/enginesync.cpp#L33), and [confirmed state](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/engine/sync/synccontrol.cpp#L144).

F06 has **no sync operation or sufficient sync/tempo ownership representation**. The profile therefore keeps `action:null`, `status:extension-needed`, `operationSpecId:mixxx.sync-enabled.v1`; no runtime executor may use that reference as a callable operation. A coordinator-owned extension must add a narrowly typed `deck.set_sync_enabled` desired-state boolean, participant-aware authority/conditions, outcome semantics and F08 tests before semantic use. Until then F08 must reject it as an unknown action. One-shot `beatsync`, `beatsync_tempo`, `beatsync_phase`, explicit `sync_mode` and MIDI-clock synchronization are outside this profile. This does not claim that MIDI clock synchronizes Mixxx.

## Presence, feedback and evidence boundaries

Boolean value feedback accepts only `00` or `7F`; intermediate values are invalid feedback even though positive command values are accepted. Volume feedback decodes as `v/127`; crossfader feedback uses its centered curve. Cue signal packets remain diagnostics as described above.

Reserve each presence packet's value `00` for **confirmed unavailable**, `40` for **unknown**, `7F` for **present**; other values are invalid. These packets describe presence only, never readiness/authority. A present play control on an empty deck cannot authorize play, and passthrough rejection cannot be disguised as an absent sync control.

The mapping must establish exact group/key existence before interpreting zero, connect the required observation callbacks and validate readings. The released script API returns zero on an unknown control; `getValue()==0` or `getParameter()==0` cannot establish presence. A valid `makeConnection` result supports existence of that control, while failed subscription alone cannot distinguish absence from mapping failure: emit unknown unless absence is separately established. Require the complete configured read/write pair. Keep connection objects and clean them up on shutdown. [Tagged scripting implementation](https://github.com/mixxxdj/mixxx/blob/2.5.6/src/controllers/scripting/legacy/controllerscriptinterfacelegacy.cpp#L134).

Selected future cadence is a presence-before-value initial burst per control, then actual sampled refresh every **100 ms** and change callbacks. Periodic presence refresh is also required. Expire each presence and reading after **500 ms** without a valid refresh. These are design limits awaiting measurement, not observed freshness/latency guarantees. Suppress value packets when unavailable/unknown; clear older values when that presence arrives. Treat missing startup/reconnect packets as unknown. Never fabricate zero-filled snapshots. Reconnect invalidates prior values, IDs and authority; it never rearms or resends old actions.

Conventional packets have **no request IDs, action IDs, track identity, connection generation, source timestamp or actor identity**. They cannot establish atomic snapshots, track binding, causal acknowledgement or deduplication. Presence refreshes are also unversioned; a delayed old packet could arrive after a newer presence change. Before promoting readings to F07 observations, later integration must bind the actual endpoint/session/profile and current track generation through independent evidence, establish freshness/queue/clock bounds, and reconcile reordering. Until those conditions are proven, keep packets in raw diagnostics or unknown/stale state. Node receipt time alone is not host observation time. No automatic semantic success follows from a matching byte or successful send.

Use `acknowledgement:none`, `deduplication:none` and unknown actor attribution for any eventual F07 write binding using this route. Never echo the outgoing command as feedback. Already-satisfied setters require actual refresh, since no change event may fire. Missing essential feedback invokes the later fail-closed/disarm policy; a timeout does not authorize replay. Physical-controller/UI writes may produce identical feedback and cannot be labeled AI or human without additional source-linked evidence.
